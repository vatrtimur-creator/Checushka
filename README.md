# Rust Util

Статическая утилита для Rust: идентификаторы Steam, локальные заметки по игрокам, расчёт рейда и переработки. HTML, CSS и JavaScript без фронтенд-фреймворков. Flask, SQLite и сервер не нужны: репозиторий можно целиком разместить на GitHub Pages.

Исходники: [vatrtimur-creator/Checushka](https://github.com/vatrtimur-creator/Checushka).

## Локальный запуск

```sh
python3 -m http.server 3000
```

Откройте `http://localhost:3000`. Страницы `/`, `/raider/` и `/recycler/` доступны напрямую. Все пути внутри проекта относительные, поэтому сайт работает и в подкаталоге `/<repository>/`. Открытие через `file://` не поддерживается: браузер блокирует ES-модули и OCR worker.

Для проверок требуется Node.js 22 или новее. Тестовые зависимости не загружаются в браузер.

```sh
npm ci --ignore-scripts
npm run verify
npm run build
```

Сборка копирует готовый сайт в `dist/`. Для Pages сборка не обязательна: HTML и браузерные ресурсы уже находятся в корне репозитория. Python не нужен на хостинге.

## GitHub Pages

В новом репозитории откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку **main**, каталог **/ (root)** и сохраните. `.nojekyll` исключает обработку Jekyll. Адрес проектного сайта: `https://<owner>.github.io/<repository>/`.

GitHub Pages доступен для публичных репозиториев на GitHub Free; для приватных требуются подходящие платные тарифы GitHub. Приватность репозитория не меняется автоматически. Если репозиторий приватный, сначала решите, можно ли публиковать исходный код, и только затем измените видимость либо используйте тариф с Pages для приватных репозиториев.

В `.github/workflows/checks.yml` есть CI-проверки. На странице Actions может потребоваться разрешить их выполнение. Для публикации используется режим **ветка/корень**, а не Actions: дополнительных токенов, CNAME и секретов нет. Успешный локальный тест сам по себе не означает, что Pages уже опубликован.

## Steam: что проверяется

Чекер валидирует SteamID64 индивидуального аккаунта через битовые поля `BigInt`. Принимается 17-значный ID или URL `https://steamcommunity.com/profiles/<id>`. Произвольные ссылки, vanity-адреса `/id/`, query-параметры и логин/пароль в URL отклоняются. Формат идентификатора не подтверждает существование игрока.

По умолчанию у игрока нет выдуманного имени, аватара, часов или статуса «онлайн». Для этих данных нужен внешний HTTPS API с CORS: [контракт подключения](docs/STEAM-API.md). API-ключи никогда не включаются в клиентский код. Открытие страницы профиля Steam не используется как проверка онлайна.

Трекер хранит до 1000 игроков в `localStorage`: без дубликатов, с заметками до 2000 символов. Список экспортируется в JSON и импортируется с объединением без перезаписи существующих заметок. После перезапуска статус сбрасывается в «неизвестно», чтобы устаревшие снимки не выглядели текущими. Настройки темы, языка, размера текста и навигации хранятся отдельно. Данные привязаны к origin сайта: локальный сервер, Preview и Pages имеют отдельные списки. Перед очисткой браузера сделайте экспорт.

## OCR и приватность

Tesseract.js 6.0.1, core 6.0.0 и английская модель поставляются локально в `assets/vendor/`. Они загружаются только при первом запуске распознавания. PNG/JPG ограничены 16 МБ и 20 млн пикселей. Есть превью, drag-and-drop, прогресс, отмена и выбор из нескольких распознанных SteamID.

Скриншоты обрабатываются WebAssembly worker в браузере, не отправляются на OCR-сервер и не сохраняются в трекере. HTTP-запросы нужны для загрузки локальных файлов worker и модели. Работа на слабом мобильном устройстве может занять время; при ошибке остаётся ручной ввод. Движок не использует языковые модели или генеративный ИИ.

## Игровые данные

Каталог и рецепты закреплены по commit SHA, с хешами исходных файлов. Это снимок, а не обещание актуальности после каждого обновления Rust. Полные источники, дата, условия и различия моделей описаны в [документации данных](docs/DATA.md).

**Рейд пока является моделью прямого урона, не точным игровым списком закупки.** Снимок build 25824447 обновлён 10 октября 2026. Для каменной стены он даёт 13 сатчелов, тогда как Rust Wiki — 10; для разрывных патронов — 200 против 185 с SAR в справочнике. Это предупреждение показано и на странице расчёта. Источник нужно заменить или дополнить проверенной игровой моделью прежде, чем использовать все значения для реального рейда.

Рейд рассчитывается для каждой отдельной цели: `ceil(HP / damage) × quantity`. Варианты сортируются по сырой сере с учётом целых партий крафта. Количество зарядов разных типов не используется как критерий выгодности. Смешанные атаки, огонь и урон по соседним целям не оптимизируются.

Переработка суммирует ожидаемый выход: `base_output × efficiency × quantity`. Дроби не превращаются в гарантированные целые ресурсы. Используются полная прочность и базовая эффективность выбранного переработчика; бонусы powergrid не применяются. Время — последовательная оценка `число предметов × базовый интервал`, а не симуляция параллельных слотов и половины стака за цикл. Имена игровых предметов в каталоге сохраняются на английском, чтобы не вносить неоднозначные переводы; интерфейс доступен на русском и английском.

## Структура

```text
index.html                 Чекер и локальный трекер
raider/index.html          Рейд
recycler/index.html        Переработка
assets/common.js           Настройки, локализация, внешний API
assets/storage.js          Сохранение и проверка импорта
assets/engine.js            Чистое расчётное ядро
assets/data.js              Закреплённый снимок данных
assets/vendor/              Локальный OCR и лицензии
scripts/build-pages.py      Общая HTML-оболочка
scripts/update-data.py      Обновление снимка игровых данных
scripts/vendor-ocr.py       Воспроизводимая загрузка OCR
scripts/check.mjs           Ссылки, синтаксис, route manifest, хеши OCR
tests/                     Расчёты, хранение и DOM-сценарии
docs/                      Источники и контракт API
```

Если меняется HTML-оболочка, выполните `python3 scripts/build-pages.py` и включите сгенерированные страницы в коммит. Скрипт обновления данных описывает свои аргументы через `--help`. После изменения снимка запустите проверки и обновите документацию.
