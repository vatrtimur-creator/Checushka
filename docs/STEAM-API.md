# Внешний Steam API

GitHub Pages не запускает Flask и не скрывает API-ключи. Rust Util по умолчанию проверяет только структуру SteamID64 и хранит локальные заметки. Он не подтверждает существование аккаунта и не определяет, находится ли игрок в игре. Для никнейма, аватара, часов и статуса нужен ваш отдельный сервер.

В настройках можно указать базовый HTTPS-адрес этого сервера. В localhost-разработке допускается HTTP. Адрес не должен содержать логин, пароль, query-параметры или фрагмент. При проверке только выбранный SteamID отправляется на `GET {base}/players/{steamid}`; скриншоты и заметки не отправляются. Никаких автоматических фоновых обновлений нет.

## Ответ

Сервер возвращает `200`, `Content-Type: application/json` и следующий объект. Здесь структура, а не демонстрационные данные игрока:

```text
{
  steamid: string,          // тот же 17-значный идентификатор
  nickname: string,         // реальное имя из Steam или пустая строка
  avatar_url: string,       // HTTPS URL или пустая строка
  status: "online" | "offline" | "unknown",
  steam_hours: number|null, // минуты Rust / 60; null если недоступно
  timecreated: number|null // Unix timestamp в секундах; null если недоступно
}
```

Фронтенд запрашивает JSON без cookie (`credentials: omit`), ограничивает ожидание 12 секундами и проверяет идентификатор ответа. Недоступность приватного профиля не равна нулю часов, а HTTP 200 от страницы профиля не равен статусу «онлайн». При ошибке показывается «неизвестно».

Сервер должен разрешать CORS для вашего Pages origin, например `https://<owner>.github.io`, а не для пути репозитория. Используйте реальный разрешённый origin, ограничение частоты запросов и валидацию SteamID. Steam Web API key храните только в переменной окружения сервера. Не добавляйте ключ в GitHub Pages, localStorage или URL.

На сервере для публичных данных применяются Steam `ISteamUser/GetPlayerSummaries/v2` и `IPlayerService/GetOwnedGames/v1` с фильтром игры `252490`. `personastate` описывает присутствие в Steam, не гарантирует игру в Rust. Часы, дата создания и статус могут отсутствовать из-за приватности. Поставщик API должен сохранять это различие.

Контракт предназначен для подключения уже существующего API. В этом статическом репозитории сервер Steam API не разворачивается.
